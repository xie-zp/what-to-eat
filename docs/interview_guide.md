# 面试问答指南

## 项目定位

**问：这个项目是做什么的？**

答：这是一个食谱规划 Agent。它不只回答菜谱问题，还能根据过敏原、时间、库存和营养目标完成菜谱检索、多日菜单规划和购物清单生成。

**问：它和普通 RAG 有什么区别？**

答：普通 RAG 主要是“检索文档后生成回答”。本项目把 RAG 封装成 Agent 工具，并增加 Planner、工具执行、约束校验、循环、长期记忆和状态持久化。

## 架构设计

**问：为什么用 LangGraph？**

答：任务存在多步骤、条件分支、循环和状态持久化。普通 Chain 只能表达固定流水线，LangGraph 更适合状态图、人工确认和断点恢复。

**问：State 里保存什么？**

答：用户目标、约束、当前任务、工具调用、工具结果、菜谱证据、引用来源、菜单、购物清单和校验错误。

**问：Planner 做什么？**

答：根据当前目标和已有工具结果选择一个工具，或者在证据足够时结束规划。

**问：为什么保留规则 Planner？**

答：无 API Key、模型超时或结构化输出失败时，规则 Planner 可以保证系统继续运行，方便测试和降级。

## 工具调用

**问：Tool Registry 解决什么问题？**

答：它统一注册和执行工具，避免执行节点出现大量 `if/elif`，同时让工具可以独立测试和替换。

**问：工具如何保证输入可靠？**

答：每个工具都使用 Pydantic 输入模型，执行前完成类型、范围和数据校验。

**问：过敏原如何保证不会被模型忽略？**

答：搜索后仍会执行独立校验节点，Planner 输出中的过敏原参数也会被用户约束强制覆盖。

**问：如何阻止 Agent 无限循环？**

答：设置最大步数、检测相同工具调用、阻止重复生成菜单和购物清单，并在无法继续时明确停止。

## RAG 与 GraphRAG

**问：为什么使用 Neo4j？**

答：菜谱、食材、步骤、分类和难度存在天然关系，图数据库适合多跳关系查询。

**问：为什么还要 Milvus？**

答：图数据库擅长结构化关系，向量检索擅长语义相似度，两者解决不同问题。

**问：为什么需要 BM25？**

答：向量检索对精确菜名、食材名不一定稳定，BM25 可以补充关键词精确匹配。

**问：RRF 的作用是什么？**

答：RRF 不需要统一不同检索器的分数分布，只根据排序融合多路结果，简单且稳定。

**问：自然语言问法很多，怎么避免只靠关键词规则？**

答：查询理解分成三层。第一层从真实菜谱数据建立食材词典做实体链接；第二层可选调用 LLM
输出强类型 `QueryPlan`；第三层由确定性代码校验模型字段是否能在原文中找到。库存、过敏原、
忌口等硬约束不交给模型判断。

**问：为什么不只用向量检索？**

答：向量检索负责语义召回，不能保证库存、过敏原和时间等硬约束。系统会把 Hybrid、Neo4j
候选先融合，再执行确定性过滤；向量只负责候选相关性，不负责安全和库存事实。

**问：怎么让回答自然，同时不产生幻觉？**

答：先生成只使用工具证据的确定性回答，再让 LLM 只做语气和结构改写。模型不能新增菜名、
食材或营养信息；如果改写内容出现证据外菜名，会拒绝该结果并回退确定性回答。

**问：为什么新问题不会继承上一轮的 30 分钟和库存条件？**

答：约束分成长期安全和本轮任务两类。过敏原、忌口、长期目标持续保留；时间、天数、人数和
库存只在菜单任务或用户本轮明确修改时生效，避免新话题被旧条件污染。

**问：如何定位 Agent 为什么慢或为什么回答错？**

答：每次请求会记录 `query_analyzer`、`plan`、`execute`、`validate`、`replan`
和 `respond` 的耗时与结果。可以区分慢在模型解析、检索、约束校验还是自然表达，
而不是只看一个总延迟。项目同时支持 OpenTelemetry，可把请求、节点、工具和 LLM
组织成同一 trace，并导出到控制台或 Jaeger 等 OTLP 平台。

## 数据工程

**问：数据从哪里来？**

答：菜谱原始内容来自 HowToCook。本项目独立实现 Markdown 解析、图谱构建、Neo4j 导入和 Milvus 索引流程。

**问：如何处理上游格式变化？**

答：通过解析器测试、章节缺失检查和数据结构校验发现变化，并将原始数据与生成数据分离。

## 安全与可信

**问：怎样减少幻觉？**

答：答案只使用工具证据，返回菜谱 ID 和来源，并对过敏原执行确定性校验。

**问：为什么不能只通过提示词限制模型？**

答：模型输出是概率性的，安全和硬约束必须由代码执行。

## 测试与评测

**问：怎么测试 Agent？**

答：分为工具测试、解析器测试、图谱测试、Graph 回归测试、API 测试和真实 Neo4j 场景评测。

**问：评估指标有哪些？**

答：任务成功率、检索命中率、相关性命中率、约束满足率、引用覆盖率和延迟。

**问：目前有哪些不足？**

答：当前 54 条场景同时覆盖规则 Planner、LLM Planner 和 Hybrid Retrieval，18 条
HTTP 可靠性场景全部通过。下一阶段主要扩展更难的对抗性评测、真实用户数据闭环、
多用户权限隔离和线上监控告警。
